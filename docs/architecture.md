# План архитектуры

## Зачем всё это

Сейчас в репозитории уже есть несколько полезных кусков, но они живут в разных ветках и плохо сочетаются друг с другом. Хочется получить один проект, который можно собирать, запускать и развивать дальше.

Итоговая идея простая:
- один CLI
- одна общая модель для поиска
- отдельные модули под разные языки

## Почему стартуем от `main`

`main` сейчас самая понятная и стабильная база:
- там есть Java-реализация
- она хотя бы выглядит как цельный кусок
- там уже есть тесты


## Во что хотим прийти

В конце проект должен выглядеть примерно так:

1. `core`
   Общие сущности и общая логика поиска.
2. `cli`
   Один вход для пользователя.
3. `languages`
   Реализации для Java, Go, Python и других языков.
4. `storage`
   Работа с индексом Lucene.
5. `tests`
   Тесты на core, языки и CLI.

Это ориентир, чтобы не разрастаться хаотично.

## Что должно стать общим

Если проект будет единым, то у него должна появиться общая модель:

- `LanguageModule`
  Модуль, который умеет работать с конкретным языком.
- `CodeEntity`
  Любая сущность, которую мы хотим искать.
- `EntityKind`
  Тип сущности: класс, метод, поле, переменная, строковый литерал и так далее.
- `EntityLocation`
  Где именно это находится в коде.
- `SearchQuery`
  Не просто строка, а более осмысленный запрос.
- `SearchResult`
  Что именно нашли и как это показать пользователю.

Смысл в том, чтобы Java, Go и Python постепенно приводились к одной форме, а не жили каждый по своим правилам.

## Ближайший план

Прядок такой:

1. сохранить рабочую Java-базу
2. ввести общие контракты
3. перенести Java в новый каркас
4. потом подтянуть Go
5. отдельно оценить, как лучше встраивать Python

## Что пока не делаем

Пока не трогаем вещи, которые могут занять много времени:
- UI
- сложный язык запросов
- ранжирование результатов
- агрессивную оптимизацию

Сначала нужен просто один нормальный, собираемый, понятный проект.

## Что хочется получить в конце MVP

Минимально хороший результат для этой стадии:
- один понятный запуск
- минимум два языка в одной архитектуре
- базовые сценарии поиска, которые реально работают
- документация, по которой можно поднять проект на новом компьютере
