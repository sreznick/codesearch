# Дорожная карта

## Этап 1. Зафиксировать базу

Сначала просто приводим стартовую точку в порядок.

Что должно получиться:
- отдельная рабочая ветка
- нормальное описание того, что сейчас есть в репозитории
- понятный план, куда вообще двигаемся

Что сюда входит:
- создать ветку
- описать архитектурное направление
- не тащить в git локальный мусор вроде временного Gradle-состояния

## Этап 2. Ввести общие контракты

На этом этапе нужно договориться с самим проектом, какие у него вообще будут общие сущности.

Что должно получиться:
- базовая общая модель
- интерфейсы, от которых дальше можно строить Java, Go и Python

Что сюда входит:
- определить модель сущностей
- определить модель запросов и результатов
- определить интерфейс языкового модуля

## Этап 3. Перенести Java в общий каркас

Java сейчас — самая удобная рабочая база. Поэтому сначала приводим в новый вид именно её.

Что должно получиться:
- Java остаётся рабочей
- но уже живёт не в старом монолитном CLI, а внутри новой структуры

Что сюда входит:
- отделить CLI от логики
- вынести общие части
- сохранить тесты и поведение

## Этап 4. Подтянуть Go

После Java можно спокойно разбирать Go-ветку и брать из неё то, что реально подходит.

Что должно получиться:
- Go встроен в тот же общий путь
- поиск и индексация выглядят одинаково с точки зрения пользователя

Что сюда входит:
- разобрать `mvp-for-go`
- перенести полезные части
- выровнять формат индекса и результатов

## Этап 5. Решить вопрос с Python

Python-ветка пока выглядит наиболее отдельной. Здесь сначала нужно понять, стоит ли успевать тащить её в MVP или лучше оставить как следующий шаг.

Что должно получиться:
- либо Python встроен в общую систему
- либо честно зафиксировано, что это следующий этап

Что сюда входит:
- разобрать `mvp-for-python`
- оценить объём переделки
- принять решение по scope

## Этап 6. Довести MVP

В конце нужен уже не просто набор идей, а рабочий результат.

Что должно получиться:
- единый CLI
- понятный запуск
- тесты на основные сценарии

Что стоит показать на демонстрации:
- индексацию проекта
- поиск переменной или поля по имени
- поиск строковой константы
- поиск метода или функции по имени
- показ места в коде, где найдено совпадение
